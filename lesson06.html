1단계. 변수로 음료 두 개를 관리해 보기

지금까지 배운 변수만 사용하면 음료의 이름과 가격을 따로 보관해야 합니다. 상품이 늘어나면 name1, price1, name2, price2처럼 변수가 많아집니다.

java · 함께 입력
String name1 = "아이스티";
int price1 = 3000;
String name2 = "초코라테";
int price2 = 3500;
System.out.println(name1 + ": " + price1 + "원");

질문: 음료를 20개 추가한다면 이름과 가격이 서로 뒤바뀌지 않게 관리하려면 어떻게 해야 할까요?

2단계. 클래스에 정보 묶기

클래스는 같은 종류의 정보와 동작을 묶는 설계입니다. 우선 생성자 없이 이름과 가격 필드만 선언하고, new를 이용해 객체를 만듭니다. 아래 코드는 ProductFirst.java로 저장합니다.

java · 함께 입력
class DrinkInfo {
  String name;
  int price;
}
public class ProductFirst {
  public static void main(String[] args) {
    DrinkInfo drink = new DrinkInfo();
    drink.name = "아이스티";
    drink.price = 3000;
    System.out.println(drink.name + ": " + drink.price + "원");
  }
}

DrinkInfo는 설계도이고 drink는 생성된 객체를 가리키는 변수입니다. drink.name은 해당 객체의 이름입니다.

실습 1. 객체 만들기

상품 클래스를 정의하고 new로 서로 다른 객체를 만듭니다.

ProductDemo.java

java
class Product {
  String name;
  int price;
  Product(String name, int price) {
    // this.name은 이 객체의 필드를 뜻한다.
    this.name = name;
    this.price = price;
  }
}
public class ProductDemo {
  public static void main(String[] args) {
    Product tea = new Product("아이스티", 3000);
    Product choco = new Product("초코라테", 3500);
    System.out.println(tea.name + " " + tea.price);
    System.out.println(choco.name + " " + choco.price);
  }
}

코드를 입력하며 확인할 점

  • 이 예제의 **파일명은 ProductDemo.java**입니다. (Java 공개 클래스 이름과 일치해야 합니다.)
  • new는 클래스를 바탕으로 객체를 만듭니다.
  • 생성자는 객체를 만들 때 초기 값을 설정합니다.

4단계. 생성자가 필요한 이유

지금까지는 객체를 생성한 다음 이름과 가격을 따로 입력했습니다. 생성자를 사용하면 new Product("아이스티", 3000)처럼 만들 때 바로 초기값을 넘길 수 있습니다.

java · 함께 입력
Product(String name, int price) {
  this.name = name;
  this.price = price;
}

this.name은 객체 안에 저장된 필드이고 오른쪽 name은 매개변수입니다. 같은 이름이라도 가리키는 대상이 다릅니다. 생성자 이름은 클래스 이름과 같고 반환형은 쓰지 않습니다.

실습 3. static이 필요한 이유

개별 객체의 값과 클래스 전체에서 공유하는 값을 비교합니다.

Counter.java

java
class Hero {
  String name;
  int hp = 100;
  static int created = 0; // Hero 클래스에 소속된 공통 변수
  Hero(String name) {
    this.name = name;
    created++; // 새 객체를 만들 때 공유 개수를 늘린다.
  }
}
public class Counter {
  public static void main(String[] args) {
    Hero first = new Hero("전사");
    Hero second = new Hero("마법사");
    first.hp = 40;
    System.out.println(first.hp); // 40
    System.out.println(second.hp); // 100
    System.out.println(Hero.created); // 2
  }
}

코드를 입력하며 확인할 점

  • hp는 객체마다 따로 존재하지만 created는 클래스에 하나만 소속됩니다.
  • static 메서드는 객체를 만들지 않아도 클래스 이름으로 호출할 수 있습니다. main()과 Math.min()이 예입니다.
  • 실제 프로젝트에서는 필드를 private으로 숨기고 메서드로 접근하도록 만드는 캡슐화도 사용합니다.

추가 연습 — 은행 계좌로 객체 이해하기

5회차에서는 메서드로 작업을 나누는 방법을 배웠습니다. 이번에는 은행 계좌를 객체로 만들어 잔액을 직접 저장하고, 입금·출금 기능을 계좌마다 관리해 봅시다. 실제 금융 서비스가 아닌 연습 프로그램입니다.

1. 계좌를 객체로 표현하기

계좌에는 주인(owner)과 잔액(balance)이 있습니다. 이 두 값을 BankAccount 클래스의 필드로 묶습니다. BankAccount("민수", 10000)은 이름과 처음 잔액을 전달해 객체를 생성합니다.

deposit(5000)을 호출하면 account 객체의 balance가 바뀝니다. main()에서 별도로 잔액 변수를 다시 저장할 필요가 없습니다. 메서드가 해당 객체의 필드를 직접 변경하기 때문입니다.

2. 먼저 결과 예상하기

처음 잔액은 10,000원입니다. 5,000원을 입금하고 3,000원을 출금한 뒤 20,000원을 더 출금하려고 합니다. 최종 잔액은 얼마일까요? 왜 그렇게 생각했나요?

3. 출금과 잔액 조회 완성하기

파일명: BankDemo.java. BankAccount와 BankDemo는 하나의 파일에 작성합니다. public 클래스 이름과 파일명을 같게 해야 합니다. TODO 두 곳을 완성하고 실행하세요.

추가 개념 — private으로 잔액 보호하기

은행 계좌의 잔액을 누구나 직접 바꿀 수 있다면 문제가 생길 수 있습니다. private은 해당 클래스 내부에서만 접근할 수 있게 제한하는 키워드입니다. 잔액은 입금·출금 메서드를 통해 변경하고, 조회 메서드를 통해 확인하도록 해 봅시다.

BankAccount.java — 개념 예시

java
class BankAccount {
  private int balance;

  BankAccount(int balance) {
    this.balance = balance;
  }

  void deposit(int money) {
    if (money > 0) {
      balance += money;
    }
  }

  int getBalance() {
    return balance;
  }
}

생각해 보기: 클래스 밖에서 account.balance = 1000000;을 실행하려 하면 왜 오류가 날까요?

교사용 정답 보기 · private

balance가 private이라 클래스 바깥에서 직접 접근할 수 없기 때문입니다. 입금은 deposit()으로, 조회는 getBalance()로 처리합니다.

이번에는 private으로 데이터를 보호한다는 의미만 익힙니다. 다른 접근 제어자와 getter·setter의 자세한 사용법은 다음 과정에서 배웁니다.
